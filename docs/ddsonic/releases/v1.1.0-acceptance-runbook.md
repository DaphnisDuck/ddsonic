<a id="rules"></a>
## Rules

[Back to checklist](#checklist)

- **PASS** means the stated condition held, the owner observed it, and the evidence was captured.
- **FAIL** means the check ran and the condition did not hold.
- **INCONCLUSIVE** means no verdict was possible: a missing precondition, an event not provoked, a failed inspection command, or the environment. The acceptance tool records it as `blocked` ([live.md](../acceptance/live.md#ground-rules)). It is never a pass.

The gate rules are in [acceptance.md, The gate](../acceptance.md#the-gate) and apply unchanged:
- only `pass` is a pass, and an environment limitation never passes;
- BLOCKER and HIGH block publication, and an unfixed MEDIUM needs the owner's written waiver;
- nothing may remain `investigate`.

Live cases only read the account. On the Spotify search screen, never press `p` ([live.md](../acceptance/live.md#spotify-live-search)). An agent never approves, waives, tags, publishes, invents a date or launches UltraReview.

**Owner decisions already recorded (2026-11-10):**
- LIVE-SPOT-005 is not run, and the account is not changed ([live.md](../acceptance/live.md#account-changes)); it is recorded as `not run` under the owner's v1.1.0 exception. The coverage limit (the real-account transition is verified only against fakes) is stated in the release decision.
- MP3 and Vorbis memory: **no exception exists for v1.1.0.**
- The owed live checks remain candidate obligations and cannot be passed on historical evidence.

**Pre-tag results are supplemental.** P1-P6 run on B0, which is not the candidate. Hand-recorded results must name the exact archive and binary ([acceptance.md, Artifact identity](../acceptance.md#artifact-identity), [The gate](../acceptance.md#the-gate)), and the live binary is the draft archive's ([live.md](../acceptance/live.md#ground-rules)). **Formal acceptance repeats the owed checks in [T5](#t5).** Counting pre-tag results would need a policy exception, explicitly scoped and made by the owner.

## Setup

[Back to checklist](#checklist)

Keep evidence in a private working directory outside the repository, here called `$REL`, with one folder per ID. Record the binary's SHA-256 and `--version` with every result. GitHub text says "the owner's Linux workstation" and names no machine, user or path.

<a id="b0"></a>
**B0, the pre-tag test binary.** This is the [dry run](../releasing.md#a-dry-run-on-your-machine) at the commit to test, with a test version not used before (`v1.1.0-test.1` is taken). It stops at the first failure:

```sh
git clone https://github.com/DaphnisDuck/ddsonic.git "$REL/src" && cd "$REL/src" &&
git checkout --detach <commit> &&
docker build -t ddsonic-build -f packaging/Dockerfile packaging && mkdir -p dist &&
docker run --rm -v "$PWD":/src:ro -v "$PWD/dist":/out ddsonic-build \
    /src/packaging/release.sh v1.1.0-test.2 "$(git log -1 --format=%ct)" &&
cd dist && sha256sum -c SHA256SUMS && tar -xzf ddsonic-1.1.0-test.2-linux-amd64.tar.gz &&
BIN="$PWD/ddsonic-1.1.0-test.2-linux-amd64/ddsonic" && sha256sum "$BIN" && "$BIN" --version
```

The expected output is `ddsonic version v1.1.0-test.2 (commit <commit>)`. A plain `make build` also works but is not the release build path.

<a id="freshhome"></a>
**Fresh home (P1-P3).** `HOME` alone does not isolate ddsonic: `CLIAMP_CONFIG_DIR`, `XDG_CACHE_HOME` and `XDG_MUSIC_DIR` also apply ([files.md](../files.md)). The socket path limit means the home should be short:

```sh
H=$(mktemp -d /tmp/ddh.XXXXXX) && mkdir -p "$H/cfg" && chmod 700 "$H"
run_fresh() { env -u CLIAMP_CONFIG_DIR -u XDG_CONFIG_HOME -u XDG_CACHE_HOME -u XDG_MUSIC_DIR \
  HOME="$H" DDSONIC_CONFIG_DIR="$H/cfg" "$@"; }
```

Do not run another ddsonic at the same time. With `HOME` changed, ALSA does not read `~/.asoundrc`; copy it into `$H` if you need it, and note that you did.

<a id="counts"></a>
**Inspection helpers (P4, T5, T6).** A count is trusted only when its command succeeded; these print INCONCLUSIVE instead of a false 0. They work in bash and zsh:

```sh
procs() { out=$(pgrep "$@"); rc=$?          # pgrep: 1 = no match, >1 = error
  case $rc in 0) printf '%s\n' "$out" | wc -l | tr -d ' ' ;; 1) echo 0 ;;
  *) echo "pgrep error $rc: INCONCLUSIVE" >&2; return 2 ;; esac; }
tmpcount() { d=${TMPDIR:-/tmp}              # -H follows the folder itself if it is a symlink
  [ -d "$d" ] && [ -r "$d" ] && [ -x "$d" ] || { echo "cannot read $d: INCONCLUSIVE" >&2; return 2; }
  out=$(find -H "$d" -mindepth 1 -maxdepth 1 -name "$1" -print) || { echo "find failed: INCONCLUSIVE" >&2; return 2; }
  if [ -z "$out" ]; then echo 0; else printf '%s\n' "$out" | wc -l | tr -d ' '; fi; }
```

Run them with the player's `TMPDIR`. If a helper prints INCONCLUSIVE, the check is INCONCLUSIVE.

### P5. Process-memory trend: SUPPORTING EVIDENCE ONLY

[Back to checklist](#checklist) · OWNER · Method: [acceptance.md, Decoder items](../acceptance.md#decoder-items-corrections-2026-11-10).

> **This is not the codec-specific measurement.** acceptance.md records the MP3 and Vorbis measurements as BLOCKED until the codec a track opened can be verified; a run made anyway "is recorded as a process memory trend with the codec unknown". **P5 never satisfies either measurement. Both stay BLOCKED and OWED, and no exception exists for v1.1.0.** A P5 result is never PASS.

Run arms (a), (b) and (c) exactly as acceptance.md describes, each in a fresh process started as `GODEBUG=gctrace=1 "$BIN" 2> gctrace.log`. Find the PID with `pgrep -nx ddsonic` and confirm it with `ps`. At N = 0, 20, 40 and 80 tracks started, pause for about 5 minutes, then:

```sh
{ echo "N=__ $(date -Is)"; grep -E 'VmRSS|RssAnon|VmHWM|Threads' /proc/$PID/status
```

**Report per arm:** the values at each N, and the RssAnon slope in KiB per track started, all labelled "codec unknown".

**How to read it:**
- **Bounded**, or a **small slope**: a trend only.
- **Material or unbounded growth:** the release rule in acceptance.md applies, and the owner decides.
- **INCONCLUSIVE:** an arm did not reach N=80.

### T1. Archive identity, checksums and manifest

[Back to checklist](#checklist) · OWNER · Source: [acceptance.md, Artifact identity](../acceptance.md#artifact-identity).

Every gating step ends in `|| exit`, so the block stops at the first failure even inside a larger command. Exit 1 is a FAIL; exit 2 is INCONCLUSIVE.

```sh
( set -u; cd "$REL/linux" || exit 2
  COMMIT=<40-hex>; N=ddsonic-1.1.0
  sha256sum -c SHA256SUMS || { echo "checksums: FAIL or file missing"; exit 1; }
  T=$(mktemp -d) || exit 2; trap 'rm -rf "$T"' EXIT
  tar -xzf "$N-linux-amd64.tar.gz" -C "$T" || exit 2; B=$T/$N-linux-amd64; M=$B/RELEASE-MANIFEST.json
  cat "$M" || exit 2
  grep -q "\"source_sha\": \"$COMMIT\"" "$M" || { echo "manifest source_sha: FAIL"; exit 1; }
  BSUM=$(sha256sum "$B/ddsonic" | cut -d' ' -f1); [ -n "$BSUM" ] || exit 2
  grep -q "\"binary_sha256\": \"$BSUM\"" "$M" || { echo "manifest binary_sha256: FAIL"; exit 1; }
  grep -q '"go_version": "go1.27.4"' "$M" || { echo "manifest go_version: FAIL"; exit 1; }
  VER=$("$B/ddsonic" --version) || { echo "binary did not run: FAIL"; exit 1; }
  [ "$VER" = "ddsonic version v1.1.0 (commit $COMMIT)" ] || { echo "version: FAIL ($VER)"; exit 1; }
  DYN=$(readelf -d "$B/ddsonic") || { echo "readelf failed: INCONCLUSIVE"; exit 2; }
  if printf '%s\n' "$DYN" | grep -E 'Shared library:.*(FLAC|vorbis|ogg|mpg123)'; then echo "NOT static: FAIL"; exit 1; fi
  echo "ALL OK: manifest, version, static"; echo "binary $BSUM"
); echo "T1 exit $?"
```

- **PASS:** `ALL OK` and `T1 exit 0`.
- **FAIL:** any mismatch. The candidate is abandoned and the fix ships as the next number; the tag is never moved.

**Goes to:** the release record and #156.
